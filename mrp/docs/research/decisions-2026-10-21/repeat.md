## 结论

重复语料的折算，推荐用 Muennighoff 的指数饱和公式，R\* 取 10。

- **推荐值**：练 4 遍约等于 3.6 遍新数据（利用率 90%）。
- **原版**：2.46 遍，偏紧。
- **改动包**：1.7 遍，偏紧得多。比所有查到的实测或拟合都低一半以上。
- **定 R\*=10 的原因**：在游戏现行的 4 遍上限内，R\* 取 7.5 到 15，结果只在 3.47 到 3.72 之间，所以定哪个值影响不大。

## 推荐公式和常量

E = 训练 token ÷ 语料池 token（游戏里就是“练了几遍”）。

- E ≤ 1：不折算。
- E > 1：等效新数据遍数 = 1 + R\*·(1 − e^(−(E−1)/R\*))。
- 每个 token 的利用率 = 等效遍数 ÷ E，乘在数据质量上（和现在的 `repeat` 位置一样）。
- 常量：R\* = 10，放进 `data/balance.js`，P4.2 校准区间取 7.5 到 15。
- 上限：新数据最多值 1+R\* = 11 遍，再练也到不了。
- 来源：Muennighoff 等 2023 的 Eq.5。R_D 是“遍数减 1”，原文拟合 R\*_D = 15.39（附录 A，表 1 写 15.3878）。

|---|---|---|---|---|---|---|
| **推荐 R\*=10，等效新数据遍数** | 1.00 | 1.95 | **3.59** | 6.03 | 8.77 | 10.80 |
| 　利用率 | 100% | 98% | 90% | 75% | 55% | 27% |
| 论文原值 R\*=15.39 | 1.00 | 1.97 | 3.73 | 6.62 | 10.58 | 15.17 |
| 区间下沿 R\*=7.5 | 1.00 | 1.94 | 3.47 | 5.55 | 7.48 | 8.46 |
| 区间上沿 R\*=15 | 1.00 | 1.97 | 3.72 | 6.59 | 10.48 | 14.89 |
| 原版 v0.9（遍数^0.65） | 1.00 | 1.57 | 2.46 | 3.86 | 6.06 | 11.00 |
| 改动包（1+0.35·log2 遍数） | 1.00 | 1.35 | 1.70 | 2.05 | 2.40 | 2.86 |

推荐曲线里，第 N 遍的边际价值约等于 e^(−(N−1)/10)：

| 第几遍 | 2 | 4 | 8 | 16 | 40 |
|---|---|---|---|---|---|
| 值多少遍新数据 | 0.90 | 0.74 | 0.50 | 0.22 | 0.02 |

大白话：前 4 遍几乎等于新数据，第 8 遍值一半，第 16 遍只值两成，第 40 遍基本白练。

**两种旧做法相当于多大的 R\*：**
- 原版 4 遍 2.46，相当于 R\*≈1.8。
- 改动包 4 遍 1.7，相当于 R\*≈0.7。
- 文献里的拟合在 7.8 到 31，最低也比改动包高 10 倍。

**第 2 遍值多少：**

## 为什么选 10

1. 唯一在大模型上直接测过的是 Muennighoff 2023。
   - 范围：7M 到 9B 参数，最多 9000 亿 token，拟合用 1 到 500 遍。
   - 结果：8.7B 模型练 4 遍，验证 loss 只比 1 遍高 0.5%（§6）。
   - 局限：数据是 C4，模型是 GPT-2 架构。
2. 后来的重新拟合散得很开：
   - Lovelace 等 2026：7.756（权重衰减 0.1，表 13）、12.731（权重衰减 1.0，表 14）。他们对 Muennighoff 的 C4 数据重拟合得 23.82（表 15）。
   - Prabhudesai 等 2025（NeurIPS）：自回归模型 31.19（表 1b；正文写 31.93，待核实）。
3. 2026 年的小模型直接测量偏低（Xiong，arXiv 2610.05591）。
   - “价值减半”的遍数 R_c = 2.7·(D/N)^0.24，tokens-per-parameter 为 20 时约 5，为 300 时约 10。
   - 在 tokens-per-parameter 300 下，练 8 遍时每个重复 token 约值 0.65 个新 token。R\*=10 给出 0.72，R\*=15.4 给出 0.80，R\*=7.8 给出 0.66。
4. 游戏里模型参数相对语料池很小（70B 对 15T，约 0.005）。按 Xiong 的损失公式，4 遍的额外损失在 0.001 以下，所以高位值不会离谱。
5. 取 10 是在“小模型实测 5 到 8”和“论文 15.4”之间偏保守取整。

- `repeatEfficiency()` 抽成函数。

推荐做法是原样搬这套结构，只换公式本体：

```js
// data/balance.js
export const REPEAT_RSTAR = 10;                 // 区间 7.5–15，P4.2 校准
export const effectiveEpochs = (E, rs = REPEAT_RSTAR) =>
  E <= 1 ? E : 1 + rs * (1 - Math.exp(-(E - 1) / rs));
export function repeatEfficiency(poolT, trainT, rs = REPEAT_RSTAR) {
  if (!(trainT > 0)) return 0;
  if (!(poolT > 0)) return 0.3;                 // 保持现有“没语料”兜底
  return Math.min(1, effectiveEpochs(trainT / poolT, rs) / (trainT / poolT));
}
```

```js
// previewProject（仅 LLM）：const repeat = repeatEfficiency(pool.tokens, tokens);
// projectTick 每段（用当时的池子）：
const rep = repeatEfficiency(pool.tokens, pj.tokens);
pj.acc.effectiveQ += frac * pool.quality * rep;   // 训练信号：打折
pj.acc.repeat     += frac * rep;
// finishPretrain：
llmBase(pj.structure, pj.tokens, pj.acc.effectiveQ / w, mix, pj.acc.q / w); // 容量不扣
// UI：把“质量打折”改成“等效 N.N 遍新数据”，用 effectiveEpochs(E)
```

算力成本不变：仍按全部 E×池子 token 付，只打折收益。
