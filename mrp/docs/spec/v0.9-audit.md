## 0. 结论速览

1. **四个新需求现在都没有落脚点**
   - 开源/闭源有两套来源，互相打架：公司级 `s.company.open` 和每个模型自己的 `m.open`。
   - 历史型号名在开局时无条件发放。
   - 全游戏没有 SOTA 概念：蒸馏上限是"老师 +1"，几个老师还能拼出比任何一个都强的模型。
   - 没有国策系统，`s.focus` 这个名字已经被团队任务占用。
2. **"R1 比 o1 强"是数据问题**
   - DeepSeek-R1 76.4 > Claude 3.5 Sonnet（新版）74.8 > o1 74.6。整条时间线上，只有这一个月是开源模型当 SOTA。
   - o1 一次都没当过 SOTA。
3. **三处破坏连贯性的 P0**
   - 开源/闭源双轨，外加 2023-07 按日期弹出的 `open_question`。机器人会在这个弹窗里把闭源公司全变成开源。
   - 命名系统四套叠加，正则还有 bug，会出现"Perplexity 71.0"这类名字。
   - "里程碑"一词同时指两套系统（董事会目标和条件里程碑）。
4. **遗留代码**
   - 旧版 v0.5 整套（legacy.html、src/engine、src/ui，约 2.2 万行）还在，并且有 120 项测试在测它。
   - v0.8"历史时刻"路径已经是死代码；rp、按月推进、周制的残留散落各处。
5. **需要先让用户拍板的点**
   - (a) 发布时是否还允许在意识形态范围内勾选开源。这和 docs/NEXT.md:5"开不开源由玩家决定"冲突。
   - (b) 改 R1 数据会改变 DeepSeek y2025 的开局。
   - (c) QwQ-32B-Preview（2024-11）算不算"第一个开源推理模型"。
   - (d) 旧版是归档还是删除；旧版里的 BYOK（自带密钥）对话要不要保留。

**建议施工顺序：**
1. `git init`，做一次初始提交。
2. 归档旧版，迁移两份 catalog。
3. 补地基：统一 `applyEffects`，统一 `sotaAt` 和 `cond()`，`migrateGame` 改为分版本迁移。
4. 修对手数据，补 SOTA 测试。
5. 意识形态收口。
6. 命名改成玩家起名，历史名改为条件授予。
7. 做国策树。
8. 把按日期触发的抉择改成条件触发。

### 1.3 流程

**每天：tickDay（402-434）**
- 依次运行：
  - `dailyFocus`（367-399）：团队任务，后训练每天涨 gain×DAY×0.8；研究任务会降 distillDep。
  - `knowTick`。
  - `researchTick`：研究完成时 `milestoneFire({on:'tech'})`。
  - `projectTick`（965）：每天 f=1/30；炸炉时，轻度当天进度 ×0.55，严重则回退 25%。
  - `dailyOrders`：交付 GPU、走私货、租卡、数据、蒸馏。
  - `dailyDeploy`：灰度期满时切换 live/smallLive，第一次上线旗舰时自动开产品，国内公司同时开始备案。
- s.queue 非空时不推进。
- 月末那天按顺序跑 `monthClose`、`startOfMonth`、`releaseScheduled`。
- 月结期间入队的事件，除 notice 和 goal 外，都挪进 scheduled，落在下月第 0-19 天（421-425）。

**月结：monthClose（911-962）**
1. 服务模拟；本月有蒸馏时先扣掉一部分推理卡（914-918）。

3. `updateReputation`（1035）、`serviceDynamics`（1052）、hype（来自 NVDA 股价）、估值。
4. `capitalProcesses`（1070）、`legalTick`（1106）。

**研究**
- 研究槽数 1-5。
- 工作量 = cost × 3.5 × `LEVEL_MULT`（按 `TECH_SRC` 的公开程度；玩家自家线的现实条目不算公开）+ 超前惩罚。
- 速度受团队规模、团队任务（研究 1.7、训练/维护 0.4、待命 0.7）、know、士气、distillDep 影响。

**蒸馏，两条路**
- (a) 买蒸馏数据：`distillOptions`（520）→ 14 天后 `applyDistill`（571）。写入 data.distill 和 teacherCap（各维度取历来所有老师的最大值）；`postPreview`（258-265）只在蒸馏档位高于自有数据档位时，把主维度上限设为 teacherCap+1。

**开局**
- 开局继承两款真实模型：rel 是开局当月或之前最新的发布；next 是 4 个月内（2026 剧本 6 个月）的下一次发布。

### 3.3 SOTA 与"最强对手"的定义

**[P0] 没有 SOTA，几套"最强"定义互相打架**

- bestClosedQ（milestones.js:11-20）：不算 extra，算玩家的闭源模型。
- bestRivalQ（21-29）：算 extra。

- distillOptions 不算 extra（game.js:524），distillTeachers 算（model.js:205-210）。
- economy 的 productQ（12-19）是另一套公式。
- 修法：统一成一个 `sotaAt()`。

**[P1] latestRelease 取的是"最新"不是"最强"（rivals.js:340）**
- 家族倒退：o1→GPT-4.5（2025-02）、Gemini 3 Pro→3 Flash（2025-12）、3.1 Pro→3.5 Flash（2026-05）、Llama 3.1 405B→3.3 70B（2024-12）、Opus 4.8→Sonnet 5、RWKV-6 14B→RWKV-7 2.9B。game.js:73-78 只给 2026 开局打了补丁。

- 2025-02 起 o1 从榜单和蒸馏选项里彻底消失。

**[P1] overallQ 在 2024-06 断层（model.js:358-359）**
- 这个月起 agent 计入平均：GPT-4o 75.3 → 66.6，SOTA 从 75.3 掉到 70.8。

- 里程碑的 minQ 是绝对值（ms_gpt4 67、ms_million_ctx 70、ms_open_frontier 62），前后难度不一样。
- 修法：agent 从一开始就按固定权重计入，或者门槛改成相对 SOTA 的差距。

**[P1] 兄弟线规则不统一**

- 修法：用公司级 org id 统一规则。

**[P1] 对手发布当月 1 日起就"存在"**

### 3.4 蒸馏【P0】

**上限可以超过老师**
- 主维度上限 = teacherCap + 1（model.js:262-264）。合成实验：o1 数学 87，练到 88.0。

**几个老师可以拼出一个更强的**
- teacherCap 逐维取历来所有老师的最大值，永不衰减（game.js:573）。
- 实测：
  - o1 + R1 + Claude 3.5 Sonnet（新版）拼出 Q 79.2，高于 2025-01 的 SOTA 76.4。
  - mistral y2025 蒸馏 8 家后同样能到 79.2。
  - qwen y2026：代码上限 95、数学 96（来自老师），知识 92、写作 94、Agent 99（来自自有数据），综合约 95，高于当时 SOTA Opus 4.5（91.4）。

**旧上限会一直卡住新底座**
- 几年前从 GPT-4 蒸馏留下的上限，会一直卡住以后每一代新底座。

**副维度不受上限约束（model.js:277）**
- 用蒸馏数据练数学时，代码作为副维度涨到 83.3（上限应是 83）。

- qwen 蒸馏 R1 后：数学 88.5 > 老师 88；代码 85.9 对老师 82；Agent 62 对老师 45。

**二选一逻辑漏洞（model.js:258）**
- 只看档位 `dist > own`：自有数据买到同档，上限就整个消失。
- 反过来：Gemini y2025 买了一份在这个维度上更弱的老师数据，知识每月涨幅从 1.11 降到 0，被卡死。
