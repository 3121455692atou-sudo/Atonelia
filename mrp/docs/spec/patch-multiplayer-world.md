## 改了什么、怎么分期（给制作人看）

两份检查意见里的 15 条必改全修了，应改的也都修了。原型重写成三家都用现有机器人，在外置盘上重跑了 79 局。

主要改动：
1. **防刷**：终局身家只看公司的基本面估值，股价只影响炒股的盈亏。小号抬股价、公司之间互相付钱刷估值、故意破产领补贴，现在都赚不到。公司之间转的钱，收的一方只入账六成，也不算进估值。
2. **自洽**：学界起点按本局的开局档来算，开局不会再压住所有公司。技术公开程度开局按“当时学界公开了什么”初始化，之后只由各家的行为推动。冲顶力改成和在场公司比，领先的公司不会再一分都涨不动。
3. **联机**：谁通过接口蒸馏了谁，不再公开。每人的下行流量实测约 1KB/秒。
4. **和训练作业章对齐**：编号、命令清单统一，名字在送评时定。

实测下来有两点没达标：从零开局的世界，进步速度大约是真实历史的六成；大厂档 2025 年开局有一局停了 360 天没进步，2 局每年只涨约 3 分，留给 M1 调。

**分期**：M0 只加口子、不改行为，排在训练作业 P2.4a 之后，v1.0 发版前合入。v1.0 发版后的顺序是：M1 单人自洽 → M2 股市和互动、M3 服务器（这两个并行）→ M4 联机界面 → M5 部署到 hz，等你说“上线”。

# 第一部分：新章全文

## M. 自洽世界与联机（v1.1；其中 M0 在 v1.0 期间合入，行为不变）

本章规定 v1.1 新增的两种玩法：“单人·自洽”和“联机”。文中 **M0–M5 指施工包**（见 M.9 和 F2），**M.1–M.10 指本章小节**。

本章以评审选定的骨架为主，分三层合成：

| 层 | 取自 | 内容 |
|---|---|---|
| 施工骨架 | 方案 A（世界优先） | 追加发布时换掉发布表的数组身份，现有缓存自动失效；董事会目标沿用 `s.goals` 的结构，改成相对目标；单人自洽存档放进 IndexedDB |
| 世界和钱 | 方案 C（经济优先） | 技术公开按行为一步步升档；全世界共用一次月结，份额加起来正好 100%；市场规模跟着世界水平走；全行业估值池；API 蒸馏按天检测；受限开源条款 |
| 联机 | 方案 B（服务器优先） | 世界只存一份 SOTA 账本；两段式日结；三档可见性；每局一个 worker 线程；座位令牌放 cookie；客户端用镜像接口；收件箱有期限；赛后复盘页；部署到 hz |

三份方案都漏掉了三个洞，本章一并补上：
1. 蒸馏别人的模型再发布，会把领先者的难度锚点抬高（下文叫“陪跑抬锚”）；
2. 新公司首发一个弱模型，就能让持标者白拿“炼出过”；
3. 学界水平高过所有公司时，“SOTA 就是最强”不再成立。

第二轮检查意见的逐条落点见附录 M-C。

### M.1 总原则

1. **一个世界，多家公司，同一套规则。**
   - 世界是一本只存一份的公共账本，记这些东西：发布表、SOTA 标签、技术公开程度、行业第一次、榜单、客户市场、算力供给、股市、公共新闻。
   - 每家公司的状态 `s` 形状一字不改，只放自己的私事。
2. **外生的只留“天时”，也就是公司管不了的东西。**
   - 显卡：每代卡的上市日、价格、交期（`GPUS`、`LEAD`、`RENT_FACTOR`）；
   - 技术最早能开始自研的日子：现实出现前 12 个月（`AHEAD_MONTHS`）；
   - 数据集的上市日，榜单的上线日和换题日；
   - 学界自己首创的 5 项技术的公开日历（M.3.6）；
   - 不针对某一家公司的法规（`WORLD_EVENTS` 里类型为 regulation、而且不带 `by` 和 `target` 的条目，例如国内备案）；
   - E5 门槛表里标“天时”的那几条；
   - 开局那一刻的“前人遗产”：
     - 从零局：学界起点那一款开源模型（按本局设置算，M.3.7）、开局前学界已经公开的技术、开局时已经生效的管制；
     - 分岔局：开局日之前的全部真实发布和全部真实技术公开。

   有两张换算表取自真实数据，但查表时用的是本局的世界水平，不是日历：
   - 缩放律 `llmBase`：算力和数据 → 底座能力；
   - 能力 → 市场规模（M.3.8）。
3. **由公司行为产生的**：谁最强、谁先公开、价格战、出口管制、市场多大、估值多少、股价多少。
4. **史实模式不变。** 史实模式由 HistoryProvider 包住现有的写死数据，所有新口子默认走它；192 局指纹按正序、倒序跑都逐位不变。
5. **风格不变。**
   - 只有模型角色拟人化；公司、市场、股市、新闻一律写实，用大白话。
   - 主界面不加按钮，新东西放进后台和收件箱。
   - 手机上整页滚动。
6. **经济规则按“有人开小号”来设计。**
   - 一个人可能同时占两个座位，或者和朋友串通。
   - 所以凡是能把钱、估值、身家从一家挪到另一家的路子，都要有损耗、有上限、公开可查，还不能凭空造钱（M.5.8、M.5.9、M.5.10）。

### M.2 模式与开局

#### M.2.1 三种玩法

| 玩法 | 谁经营公司 | 世界从哪来 | 跑在哪 |
|---|---|---|---|
| 单人·史实（v1.0，现有） | 玩家 1 家；对手按真实数据发布 | HistoryProvider | 浏览器 |
| 单人·自洽（v1.1） | 玩家 1 家，加 2–11 家电脑公司；所有公司同一套规则 | SimProvider | 浏览器（同一页面里跑整个世界） |
| 联机（v1.1） | 2–8 名真人，电脑公司补位 | SimProvider | 服务器上每局一个 worker 线程；客户端只有 MirrorProvider（公开部分的镜像） |

自洽和联机用同一套世界代码，区别只在时钟跑在浏览器里还是服务器上。

#### M.2.2 开局方式

**从零（默认）**
- 开局年可选 2023、2024、2025。
- 所有公司都是新公司，名字自己起。
- 开局档：小作坊 `small`、初创 `specialist`（默认）、大厂 `major`，资源取 `START_RESOURCES[档][年]`。默认所有公司同一档，房主可以改成各选各的。
- 公司总数（真人加电脑）3–12 家，默认 6 家。
- **开局技术**：`createGame` 按年份发的那批技术里，只留开局时世界技术账本里已经到“论文”或“开源”的（`P().startTechs`）。其余的一律不给，因为这个世界里还没人做出来。
  - 例：2025 年从零开局时，MoE、GRPO、推理这些技术都要自己研究。
- 所有公司一开局就解锁 `adopt_open_base`，可以在学界或别家的开源权重上续训（`startJob({ kind: 'finetune' })`，T11.2）。

**分岔**
- 开局年可选 2023、2024、2025。
- 真实的 LLM 公司用现有的 `createGame` 开局。开局日之前的真实发布和技术公开都保留，算“前人遗产”；开局以后没有任何写死的发布。
- 玩家各挑一家，一家只能一个人；其余由电脑经营。图像、音乐、语音那 4 家不进（首版只开 LLM）。
- **在场家数**：
  - 默认电脑上留 12 家，手机上留 8 家（`SELF.FORK_KEEP`），房主可以改。
  - 被拿掉的公司冻结成只读的前人遗产：开局前的发布照旧可见、可以拿来蒸馏和续训，开局后不再发布。
  - 机器人按开局前最强模型从高到低挑在场的公司，真人挑的公司一定在场。
- 开局时用新规则（M.3.4）把开局前的真实发布回放一遍，得到初始的 `world.label`。各家的“炼出过”（★，`before`）沿用 `seedOf`（D10.4）。
- 历史型号名照 C2，由策略节点授予，同样受全世界唯一的限制。电脑公司一律用 adaptive 模式选策略，所以历史会走岔。

**两种开局都适用的规定**
- **时长**：结束日不晚于 `END`（2026-10）。可选 1 年、2 年（默认）、3 年；超过 `END` 的截到 `END`。
- **模态**：首版只开 LLM。
- **开局路线**：从零局在大厅里选一档，写入 `setStance(s, 档, { src: 'start' })`，之后只能靠策略改（B4 不变）。分岔局照 B6。

#### M.2.3 从零局里每家公司要定的
- **公司名**：2–16 个字，全世界唯一，不能和 24 家真实公司重名。
- **品牌词**：模型名打头的那个词。
  - 拉丁字母至少 3 个，或者汉字至少 2 个；
  - 不在通用词黑名单里（`BRAND_BLACKLIST`）；
  - 不能是 24 家公司的品牌词（`ORG_BRANDS`），也不能是任何真实型号名；
  - 全世界唯一。
- **国家**：美国、中国、欧洲。决定本土市场、能买哪些卡、要不要备案、受不受管制，规则和现有这三类公司一样。
- **两项擅长**：写进 `strengths`，给 adaptive 策略打分用。
- **开局路线**。
- **模型角色立绘**：全游戏只有这一项是拟人化的。

分岔局只挑公司，上面这些都沿用那家真实公司的设定。

### M.3 世界模型

#### M.3.1 状态怎么拆

```
world = {
  v, mode: 'zero' | 'fork', seed, rng, day, start, end, mod: 'llm', seq,
  settings,                                   // 大厅设置
  companies: { [id]: { id, name, brand, series: [], org: id, country, tier0, kind: 'human' | 'bot', seat, bot: 'easy'|'normal'|'hard'|'passive', joined, frozen } },
  rels: [],                                   // 开局后追加的全部发布行（含学界行），按追加顺序，只追加
  label: { holder, field: [], log: [], made: { [org]: [{ relId, modelId, day, q, via }] }, steadySince },
  tech: { [techId]: { level, by, since, cal } },
  ms: { [msId]: { org, relId, day } },
  acad: { q, start, startRelId, gains: [techId], publishers: [org], log: [] },
  names: { [normName]: { org, relId | evalId, pending } }, relIds: { [relId]: org }, brands: { [normWord]: org },
  market: { month, table, refPrice, tam, dStar }, supply: { quarter, orders: {}, cap: {}, rent: {} },
  flags: { export, priceWar: {}, shocks: [] }, effortRef: { T, K },
  valuation: { pool, month }, exchange: { … }（M2）, news: [], log: []
}
s（每家公司）：现有形状，一字不改
```

- **发布表版本** `ver` 就是 `world.rels.length`，不再另外存一个计数。
- 读档时调用 `setReleases(冻结的前人遗产 + world.rels)`，所以存档和快照里都带着完整的追加行（E8）。
- 冻结的前人遗产：从零局是空的；分岔局是开局日之前的真实发布。

**镜像**：每天各家推进之前，世界把下面这些写进各家的 `s`，只读，读它们的现有代码一行都不用改：

| 字段 | 内容 |
|---|---|
| `s.sota` | `projectSota(world, org, s)`，见下 |
| `s.ms` | 照抄 `world.ms`，本家的 `who` 写 `'me'` |
| `s.world.hype`、`s.world.priceWar` | 照抄世界的值 |
| `s.world.adj` | 不写。D5 的跟随者钳制只在史实模式里用 |
| `s.scheduled` | 世界把别家的发布、技术公开、点名到本公司的大事推进来 |
| `s.news` | 只放和本公司有关的；公共新闻只存在 `world.news` 里 |

`projectSota(world, org, s)` 把世界账本换算成每家 `s.sota` 的现有形状：
- **持有者 `holder`**：
  - 本家持标时：`by: 'me'`，`id` 写本家快照的模型 id。`cond.js`、`super.js`、`sota.js` 都按 `holder.by === 'me'` 和快照 id 判断，所以必须这样写。
  - 别家持标时：`by` 写那家的公司 id（就是 family），`id` 写 relId。
- **炼出记录 `made`**：换成本家的数组形状 `[{ modelId, day, q, via }]`。
- **`field`**：照抄世界的。
- **`before`**：分岔局取开局前的史实（`seedOf` 为 ★），从零局为假。
- **`seed`、`kin`**：照旧在本地算。

F4a 的“镜像一致”就按这个投影来比。

**公司身份**
- `createGameFor(spec, scenario, seed)` 先调用 `registerCompany(spec)`，把公司写进 `COMPANY_BY_ID`、`PLAYABLE`、`FAMILIES`、`START_STANCE`，然后照常走 `createGame`。org 就是公司 id，格式是 `c_` 加 6 位小写字母或数字。
- `registerCompany` 是幂等的：同一个 id、同一份 spec 再注册一次，什么都不做；同一个 id、不同 spec 就报“存档损坏”。
- `s.company` 存完整的 spec，并带 `custom: true`。`migrateGame`、`validateGame` 现在都要求“必须是 24 家之一”，遇到 `custom` 时改成检查 spec。
- 这些单例的快照、回滚和换回史实的办法，见 E8。

**学界**
- 加一条家族：`FAMILIES.academia = { org: 'academia', mod: 'llm', company: '学界与开源社区', name: '社区开源基线', brand: 0.08, region: 'global' }`。
- 学界的发布行带 `A` 标签。
- `P().isNpc('academia')` 为真（M.3.2），凡是要把学界排除在外的地方，都靠它判断。

#### M.3.4 SOTA 标签：世界只存一份账本

在 D10 的基础上改这几条：

1. **候选**：公司的全部发布，不分大小、开闭源、带不带 `S`。学界的行不当候选。
2. **场地**：本模态有发布的公司不少于 2 家，而且候选的 q 必须高于当时学界最强的 q（`labelGate`）。不满足就没有持有者。
3. **第一次挂上**：从高于学界的候选里取 q 最高的一款，同分取送评序号小的。它要领先 `FILL_LEAD`（3 分）才算“炼出”，比较的对象是“别家最强”和“学界最强”中较高的那个。
4. **挡住挑战才算数**：一款别家发布同时满足下面三条，才算一次挑战：
   - 它是那家新的最强（主线）；
   - 它的 q ≥ 持有者 − `SELF.DEFEND_NEAR`（1 分）；
   - 它的完整血统里没有持有者那家。

   这样一来，新公司或小号首发一个弱模型，或者拿持有者的模型蒸一个出来发布，都不能让持有者白拿“炼出过”。这一条改的是 sota.js `offer` 里“挡住挑战”那一支，“一家的首次发布一定算主线”本身不改。
5. **稳坐也算数**：持有者（含它自家换代之后的版本）领先“别家最强和学界最强中较高的那个”≥ `FILL_LEAD`，连续 `SELF.STEADY_DAYS`（30）天，也算炼出（`via: 'steady'`）。
   - 这样，领先最多、别家一直追不到 1 分以内的那家，不会一直被当成新手。
6. 换手、自家换代、`EPS` 照 D10.2。
7. **同一天的发布**：当天的全部发布在收盘时一起处理，先按 q 从高到低，同分按送评命令的先后（`seq`，T6.2 的 `submitEval`，跳过评测的也有）。所以同一天一家发 60.05、另一家发 60，只有前一家挂上标签。
8. **“炼出过”**：记在 `world.label.made[公司]`，永久有效；`sotaMade(s)` 读镜像，ρ 照它取值。
9. **预估**：`sotaWouldTake(s, q)` 和送评面板的授名预估读同一本世界账本，界面上标“预计：同一天别家也发的话，以收盘为准”。
10. 史实模式仍按各家视角回放，不变。

#### M.3.5 难度锚点、地板与冲顶力（D6 在自洽世界里怎么用）

**问题。**
- 世界为空时，引擎原样的出生护栏拿一个空世界当锚点，所有底座都出生在 0 分附近。
- 加上学界起点以后，又会被钳在学界之下 1 分。原型对照组（`--clamp`）里，公司第一次超过学界起点 1 分，要等开局后 553–574 天；两年末世界最强 50.1–50.9。

**不采用的解法。** 不拿真实曲线平移后当地板。方案 C 的实测显示：有了随日期上涨的地板，各家就贴着它走，世界前沿就等于一条预设线。

**定下的解法，分四条：**

1. **从头预训练的底座不过护栏，只看缩放律和算力。**
   - 自洽模式下，从头预训练的底座既不过“R − 1”护栏，也不过单科包络护栏，能力只由缩放律（`llmBase`）和算力决定。
   - 续训出来的底座锚点换成底座那一款，能力本来就不超过它。蒸馏照 D7。
   - 原型实测（附录 M-A）：
     - 初创档 2024 年从零开局，第一个底座 54.2（2024-04），2025 年中新底座跳到 71；两年末世界最强 73.2。
     - 同期真实前沿是 78.7（2024-12）、91.3（2025-12），真实开源最强是 74.3、87.3。
   - D6 仍然成立：
     - 底座往上跳一大步，要花一整次预训练的时间和卡；
     - 跳上去以后 δ > 0，后训练几乎不涨，要等别人追上来。原型里 2025-03 gamma 的新底座 71 分，锚点 55.6，`Hq = 0`；两个月后别家也发到 71，它的 `Hq` 回到 0.76。
2. **锚点的取法。**
   - 锚点 R 取下面两项中较高的：
     - 别家可见的最强，排除完整血统里有本公司的发布；
     - 学界最强，同样排除血统里有本公司的学界行，退回到最近一行不含它的（M.3.7）。
   - R 仍然不算自己（D6.4）。
   - `ownHist` 只在分岔局里用，只算本公司开局前的真实行；`histOther` 为空。
   - `ANCHOR_CACHE` 的键里加上 `P().version()`。
3. **学界只当跟随者**（M.3.7）。它给锚点兜底，但永远比公司已发布的最强低 1 分以上。
4. **冲顶力参照用在场公司的中位数**（`P().effortRef`）。
   - 每天开盘时，世界算一次：
     - T = 在场公司（不含学界，被托管的也算）训练算力的中位数 × `SELF.EFFORT_REF.T`；
     - K = 技术积累的中位数 × `SELF.EFFORT_REF.K`；
     - 两者分别不低于日历值的 `SELF.EFFORT_FLOOR`（2% 和 10%），防止空世界除零。
   - fComp、fKnow 照 D6.2 和 T4.6 的公式算，只把分母换成它；D6 的常数一个不动。
   - 原因：日历表是“真实前沿实验室开局卡数的一半”，从零局最多只有大厂档，冲顶力几乎都低于门槛 A0 = 0.3，F 接近 0，领先者后训练一分不涨。“炼出 SOTA 后的 ρ”“独门技术 fLead”“公开还是藏着”对领先者统统失效，前沿只能靠一年一次的预训练往上跳。
   - 原型实测（三家都用现有机器人）：
     - 持标者在 |δ| ≤ 1 时 F 的中位数：日历参照 0（6 局全是 0）；改用中位数参照以后 0.60（55 局里 51 局 ≥ 0.2）。
     - 世界最强连续不涨的最长天数：日历参照 239–356 天；中位数参照中位 202 天，p90 239 天。

#### M.3.6 技术公开：开局初始化，之后按行为升档

**开局初始化世界技术账本**（等级照搬，不记事件）：
- **从零局**：
  - 开局日之前的学界条目（`TECH_SRC` 里来源是 `academia`、日期 ≤ 开局月）；
  - 没有任何来源记录的老技术，开局前已到 `t.from` 的，按论文算（research.js 原有规则）。
- **分岔局**：开局日之前的全部真实条目，哪家公司的都算。

**之后照日历公开的，只剩学界自己首创的 5 项**：
- 指的是 `TECH_SRC` 里第一条来源就是学界的那 5 项：`distill`、`dpo`、`long_ctx`、`flash_attn`、`spec_decode`。这是天时。
- 学界另外那 7 条（`func_call`、`grpo`、`computer_use`、`fp8`、`const_cls`、`muon`、`sparse_attn`）是跟着真实公司走的。开局之后的部分删掉，改由自动升档从各家行为推出来。
- 真实公司的条目，开局之后的一律删掉。

**四档怎么升**（账本只在等级真正提高时记事件、发新闻）：

| 档位 | 怎么到这一档 |
|---|---|
| secret | 第一家研究完成。只有它自己知道，世界账本只记下来、不公开 |
| proof | 带这项技术的模型上线了（`snap.techs` 里有它） |
| paper | 发了技术报告（`publishPapers`，或送评时附报告） |
| open | 带这项技术的开源权重发布了 |

**其余规则**：
- **没人主动公开时自动升档**：
  - proof 满 365 天，学界照着产品把方法反推出来，升为 paper；
  - paper 再满 180 天，学界开源复现，升为 open。
  - 这两个天数都从各家行为发生那天算。由自动升档得来的 paper 照样会再升到 open；只有开局初始化和学界日历来的等级不参加自动升档。
- **最早能研究的日子照旧**：`t.from` 前 12 个月。
- **“公开还是藏着”的取舍**：
  - `techStatus` 读世界水平，自家公开的也算进去（`techSelf`）；
  - 独门技术 `fLead` 只算“自家掌握、世界上还在 secret 或 proof”的技术；
  - 一家把技术公开到 paper 或 open，别家照着学的工作量倍率就从 2.6（再加超前惩罚）降到 1 或 0.6，学界目标值 +0.4（M.3.7）；
  - 但它自己的 `fLead` 也少了一项。
- **试验**：T 章的试验（T5）不改技术账本，只能缩短在研技术的时间；研究完成时照常按“首个研完”记 secret。
- **原型实测**：初创档 2024 年开局，主配置 730 天里账本只记了 5 件真正发生的事。
  - beta 开源 Beta 1：RLHF、DPO 从论文升到开源；
  - beta 自研 GRPO（secret），第二天发技术报告（paper），开源 Beta 2.1 时升为 open。

  上一版原型里“全部由行为产生”的 15 条，有 12 条是开局前早就公开了的，这一版不再出现。

#### M.3.7 学界与开源社区（NPC）

**起点（前人遗产）**：开局那天发一行“社区开源基线 YYYY-MM”，宽松许可。

```
ACAD.START = min( 开局日之前真实开源最强 − 4,  本局最弱开局档在 4 个月内能练出的最好底座的出生 q − 3 )
```
- “真实开源最强”读冻结的真实发布表。2023 年开局之前没有真实开源发布，取表里第一款真实开源模型（LLaMA 65B，39.6）。
- “4 个月内能练出的最好底座”：
  - 用本局最弱那一档的开局状态（含 M.2.2 的开局技术），按机器人立项的枚举办法，取 `previewProject` 工期 ≤ 4 个月的配置里出生 q 最高的；
  - 大厅里改开局档、开局年时当场重算。
- 各维：取上面那款真实开源模型的各维，按 q 等比缩放（`qOf` 是加权和，等比缩放后 q 正好对上）。
- 分岔局：起点就是开局前真实开源最强那一款本身，不另发起点行。

原型实测的起点，以及第一款公司发布的 q（3 个种子的中位数）：

| 开局年 | 小作坊 | 初创 | 大厂 | 第一款公司发布（小作坊 / 初创 / 大厂） | 上一版写死的值 |
|---|---|---|---|---|---|
| 2023 | 35.2 | 35.6 | 35.6 | 40.5 / 48.7 / 49.6 | 34 |
| 2024 | 42.9 | 47.5 | 53.5 | 45.7 / 54.2 / 62.7 | 53 |
| 2025 | 48.6 | 55.5 | 66.0 | 55.1 / 58.4 / 68.9 | 70 |

所有开局的第一款公司发布都高过学界起点（高 2.8–14 分）。上一版 2025 年初创局里学界压住所有公司约 13 个月的问题，没有再出现。

**之后怎么涨：只由公司的行为推动。**
- **开源跟进**：一款公司开源权重发布满 90 天后，学界的跟进值 = 那一款的 q − 2。
- **技术扩散**：一项 LLM 技术第一次由某家公司公开到 paper 或 open（之前在 secret、proof 或没人会），学界 +0.4。每项技术只算一次，记在公开的那家名下。本来就有论文的技术再开源，不算。
- **目标值** = max(起点, 开源跟进值) + 0.4 × 扩散过的技术数。
- **上限**：任何时候都不超过“公司已发布的最强 − 1”；还没有公司发布时不动；只涨不跌。
- **怎么发**：每月最后一天收盘时算一次，目标值比现值高 0.5 以上，就当天追加一行（日期就是当天，避免下月初又被排一次，M.3.2 的 `scheduleRivals`）。
  - 各维取被跟进那一款的各维，按 q 等比缩放；没有被跟进的，就按起点那一行缩放。
- **学界行的血统**：被跟进那款的公司加它的完整血统，再加上全部技术扩散的来源公司。
  - 算某家的锚点时，跳过血统里有这家的学界行，退回到最近一行不含它的，最差退回到起点行。
  - 这样，领先者自己开源，或者盟友蒸馏它再开源，学界跟上来以后也抬不动它自己的锚点。

**用途。**
- 能被蒸馏、能被续训，所以从零局第一天就有老师；
- 在客户市场里分一点自部署的份额，品牌 0.08；
- 当难度锚点的地板。

**限制。** 学界不进 SOTA 场地，不当标签候选，不参与榜单名次，不算“行业第一次”（`isNpc`）。

**为什么“SOTA 就是最强”重新成立。** 学界永远在公司最强之下，而标签候选又必须高过学界，所以持标那款永远是世界上最强的，最多差一个 EPS。原型 79 局里，一天违反都没有。

**全员闭源的局里，学界一直停在起点。** 原型里全员闭源的 6 局，学界都没动（47.5 和 35.6）；同样种子下全员开源的 6 局，学界升到了 66.6–70.7。

#### M.3.8 市场、算力、估值：全世界共用一次月结

1. **客户市场**。`settleMarket` 在每月最后一天、各家月结之前跑一次。
   - 对每个“产品 × 地区”，参与者是：各家在售的旗舰和小模型、学界的自部署，再加一个“不用 AI”的选项。
   - 每个参与者的权重 `w = exp(k·(q − qmax)) × 品牌 × 地区系数 × 价格系数`：
     - `k`、地区系数、价格系数沿用现有 `marketShares` 的写法；
     - 品牌一律用 `playerBrand(s)` 的公式；
     - “不用 AI”的权重取 `MARKET_SELF.OUTSIDE[产品]`。
   - 份额 = `w / Σw`，所有份额加起来正好 100%。各家月结时读这张表，后面的流程照旧。
   - 原型里各家各算一遍份额再加起来，是 174%–212%。
2. **市场规模按世界水平查表**。
   - d* = 真实历史里，世界最强第一次达到本局当前最强的那一天。
   - 市场规模 = `MARKET[产品][地区](d*)`，API 参考价 = `API_PRICE[地区](d*)`，都按 90 天平滑。
   - 本局领先真实历史时，封顶在今天日历值的 1.3 倍。
   - API 质量里 agent 维的权重也按 d* 取（E5 门槛表）。
3. **算力：共用供给池，季末统一定价**。
   - **总供给**：每季度每种卡的世界总供给 = Σ 在场公司开局档的原配额（`QUOTA`）× `SUPPLY_SELF.MULT`（默认 2）。新卡上市头两个季度减半，沿用现有规则。不再按档位给每家配额。
     - 原型实测：倍数取 1 时，初创 2024 两年末世界最强 60.6–64.6；取 2 时 71.6–73.2。原配额是为 24 家史实世界定的，这里在场的公司少得多。
   - **下单**：按目录价预扣款，交期照 `LEAD`。
   - **季末结算**：本季总订单超过总供给时，全季统一价 = 目录价 × (需求 ÷ 供给)^0.5，多退少补，所有人同一个价。超出供给的部分，按各家订单量比例分配，没分到的顺延到下季度优先交付。这样第一天一次下满也占不到便宜。
   - **租卡池**：
     - 出租的卡进池子，增加租卡供给；租入的需求和它对冲。
     - 现货租金 = 那张卡自己的月租 × `RENT_FACTOR` × (需求 ÷ 供给)^0.5，不低于 0.5 倍。现在 economy.js `averageRent` 不管什么卡都按 H100 收，自洽模式里改掉。
     - 公司之间不能直接租卡，一律经过池子。
   - **出口管制**改由状态触发（M.3.9）。开局那一刻已经生效的管制状态算前人遗产。
4. **基本面估值 V**：取代 economy.js `updateValuation` 那张按日历给钱的 `TECH_POOL`。
   ```
   客户收入_i = 近 12 个月共用月结里对话、订阅、API、Coding Plan 四项的收入
                （不含公司之间的任何钱，不含出租显卡）
   行业池 P   = max( Σ 各家开局估值, Σ 客户收入_i × VALUE_SELF.MULT × 情绪 )
   情绪       = 1 + 冲击项，夹在 [0.7, 1.2]
   权重 w_i   = exp( W_REV·ln(1 + 客户收入_i / 1e7) + W_Q·(在线旗舰 q_i − 世界最强) + W_EXP·期待加成_i )
   资产_i     = 净现金 + 自有显卡回收价（买价 × 0.55，和卖卡同价）
               + 持仓按“整仓卖回池子”拿到的现金 − 空头按“整仓买回”要付的现金
   V_i        = P × w_i / Σw + 资产_i
   ```
   - 期待加成：D11 结果对估值的效果，在这里折算成这一项，90 天内线性衰减到 0。
   - 融资、增发、回购都按 V_i 定价（M.5.5），不读市价，避免估值和市值互相抬。
   - IPO 门槛和董事会目标里的“收入”，也只算客户收入。
   - 情绪只读冲击项，不读买卡量，所以大户买卡不会抬高所有人的估值。
   - 原型没有实现这一条：现有公式下，2024-10 一轮融资让现金一下子涨了约 7 倍。
5. **公司档位**。
   - 每季度按 V 排一次：前 15% 为 frontier，15%–50% 为 major，其余为 small。连续两个季度达标才升降。
   - 档位只用来定市场期待（D11）和显示，不影响买卡，因为买卡已经是共用池了。
6. **指数**（只剩两只，云指数删掉，因为没有可读的东西）：
   - **算力指数** = 100 × (本季度全世界买卡数 ÷ 开局那个季度)^`INDEX.CHIP_EXP`(0.3) × (1 + 冲击项)。
     - 冲击项来自开源冲击（M.3.9），在 90 天内线性回到 0。
     - `hypeIndex` 读它。
     - `ipoOpen` 看不含冲击项的那部分（≥ 80）。
   - **AI 板块指数**：全部上市公司按市值加权。

### M.4 一天怎么结：两段式日结（`world.tick`）

1. **命令段**。
   - 按到达顺序执行这一天收到的命令（`applyCommand`），每条命令拿一个序号 `seq`，写进日志。
   - 名字在 `submitEval` 这一步登记（M.5.4）。
   - 电脑公司的决定也在这一步做，同样分配 `seq`。
   - 系统命令同样在这里执行、写进日志，见 M.6.5：收件箱到期自动选、转托管、交还、中途接管。
2. **开盘**。
   - 如果今天是月末，先做共用月结（M.3.8 第 1、2 条）；季末做算力的季末结算（M.3.8 第 3 条）。
   - 每天都做：算 `world.effortRef`（M.3.5 第 4 条）；交易所开盘：价值资金拉回、扣借券费、执行昨天收盘判定的强平（M2）。
   - 把镜像写进各家（M.3.1）。
3. **各家推进**。
   - 各家依次跑 `tickDay`，读的都是“昨天收盘”的世界，执行顺序按公司 id 每天轮换。这一步谁也不写世界账本，所以结果和顺序无关。
   - 评测到期的候选在 `tickDay` 里的 `evalTick` 发布（T6.2）。自洽模式下：
     - `labelOnRelease` 返回 `{ pending: true }`；
     - `judgeRelease` 和快照的 `m.sota` 都挪到收盘时做。
4. **收盘**，依次做：
   1. 收集当天的新发布，先按 q 从高到低，同分按送评 `seq`，逐条 `appendRelease`；
   2. 过世界标签（M.3.4），包括稳坐检查；
   3. 登记行业第一次（M.3.10）；
   4. 更新技术账本：学界日历、各家的 secret / proof / paper / open、自动升档（M.3.6）；
   5. 月末时学界跟进，学界行写当天日期（M.3.7）；
   6. 检查触发器（M.3.9）；
   7. 交易所收盘；
   8. 给当天发布的快照补写标签结果和期待判定；
   9. 回写镜像（`projectSota`）；
   10. 别家的发布排进各家 `s.scheduled`，次日早上可见，沿用 loop.js `releaseNow` 的“标签 → 新闻 → 里程碑”链。月初不再从发布表排（`scheduleRivals = false`）；
   11. 联机时推送给客户端。
5. **卡片**。
   - 单人自洽：只有一个真人，卡片照旧会暂停游戏。
   - 联机：卡片不挡时间（`queueBlocks = false`），进收件箱（M.6.4）。

### M.5 互动玩法

#### M.5.1 互相蒸馏：三档

上限一律照 D7：`qCap = min(老师 q, worldSota) − APPROACH`。像芝诺的乌龟，只能无限接近，永远超不过老师。`worldSota` 取公司发布和学界里最强的那款，由于学界永远在公司之下，它实际上就是公司里最强的。

| 老师 | 条件 | 花钱 | 风险 |
|---|---|---|---|
| 宽松开源 LP（含学界） | 看得见就能用 | 用自家推理卡跑生成订单 | 无 |
| 受限开源 LR | 看得见就能用 | 同上，另外要遵守发布方勾选的条款（M.5.3） | 违反条款时，发布方可以打许可官司（`CASES.license`），胜率高 |
| 闭源 API | 对方有在线 API | 按对方的 API 标价每天付钱；对方按 M.5.9 只入账六成，不算客户收入。同一对公司每个游戏年最多买 2 个数据包（对方限流） | 每天都可能被查出（M.5.2） |

#### M.5.2 闭源 API 蒸馏：怎么被查出、查出以后怎么办

**检测**：按天、按“学生—老师”这一对算。识别信号参考 Anthropic 2026-02 的公告：抽取量、能力集中度、账号、防护档。
```
p(当天) = 0.004 × √(当天抽取 token ÷ 10 亿) × 集中度(只采一类数据 ×1.6) × 账号(大客户账号 ×1.5，分散小号 ×0.5) × 对方防蒸馏档(标准 ×1，严格 ×2.5)
```
- 一个 14 天、4.3G token、只采一类、用大客户账号的数据包，被查出的概率约 7%；对方开了严格防护时约 17%。
- 用分散小号要多花 40% 的钱，一旦被查出按欺诈处理，后果加倍。
- 只有真的做了 API 蒸馏才可能被查出，不会冤枉人。原来的随机替身在自洽模式下全部关掉（`standIns`）。

**查出就是证据**。
- 规格已经保证“没做就不会被查出”，所以不再看抽取量够不够一个整包。
- 指控的效果按抽取量成比例：股价冲击 × min(1, 抽取量 ÷ 一个包)。
- 只有抽取量不到 `GEN.cancelKeep`（25%）个包时，才算证据不足。这时指控方口碑 −2。
- 这样，第 13 天取消订单、拿走 93% 数据的人，照样会被成比例地追究（订单取消以后，完成 25% 以上的部分照样入库：orders.js `cancelGen`）。

**查出以后**：老师那家的收件箱里来一张卡，期限照 M.6.4，到期默认选“封号不声张”。

| 选项 | 后果 |
|---|---|
| 封号不声张 | 对方在这家的 API 订单作废，已付的钱不退；180 天内不能再买这家的 API |
| 公开指控 | 对方股价 −8%（未上市的 V 记 −5% 的期待减项），口碑 −3，都乘上面的比例；被指控的模型在榜单上挂标记，这一对的血统随之公开 |
| 起诉 | 走 `legal.openCase(CASES.tos, vendor = 老师公司 id)`，索赔已付 API 费的 3 倍，赔款按 M.5.9 入账 |
| 收授权费 | 转成正规授权：对方可以接着用，价格 ×3，从此不算违约，仍受“每年 2 个包”的上限 |

- 被查出的一方收到现有的 `distill_ban` 卡，选“承认”就只丢掉这一家老师的数据（D7 原样）。
- 新手保护期（M.5.7）不免罪：检测照常进行、照常记账，保护期一过，老师就能处置。

#### M.5.3 受限开源条款

open_restricted 路线的公司发布开源权重时勾选条款，默认全勾。delayed 和 open_family 路线放出来的旧代模型，也适用同样的条款。

| 条款 | 内容 |
|---|---|
| 署名 | 衍生模型的名字必须以发布方的品牌词开头，并标“基于 X”。C1 第 5 条对这类衍生放行。每出一款衍生，发布方品牌 ×1.01；只算 API 份额不低于 0.5% 的衍生，每家发布方累计最多 ×1.10。真实发生的署名衍生会给发布方发新闻，取代原来 `license_fork` 那个随机替身 |
| 大户分成 | 衍生模型的 API 份额达到 15% 以后，每月把客户收入的 5% 付给发布方，在共用月结里转账，按 M.5.9 入账，公开可查 |
| 禁止训练竞品 | 拿它做蒸馏就算违约 |

#### M.5.4 起名、品牌与打榜

**公司名和品牌词**：在大厅里就要求全世界唯一（M.2.3）。

**模型名**：
- 全世界唯一。`claimName` 同时检查 `normName`、`relId` 和原样名字三样，三样都没被占才行。（`normName` 会去掉括号里的内容，`relId` 不会，所以“Beta(1)”和“Beta1”会撞 relId。）
- **送评时登记**：
  - `submitEval` 执行的那一刻登记（跳过评测、当天发布的也一样），评测期间一直占着，`cancelEval` 时释放。
  - 同一天第二家想用同一个名字，送评时就被拒，提示“这个名字已经被别家预订了”。送评中的名字不说是谁订的，免得泄露别家在练什么。
  - 已经发布的名字照常提示“已被 X 公司的 Y 用了”。
  - 自洽模式下 `evalTick` 发布时不会撞名，所以不加后缀（C7）。
- 全部真实型号名（约 300 个，读冻结的真实发布表）永远保留；历史名只能由策略授予，只在分岔局里有。
- 不能以别家的品牌词或系列词开头，署名衍生（M.5.3）除外。

**系列词**：每家最多登记 2 个，第一次用某个词发布模型时登记。要求至少 3 个字母或 2 个汉字，不在黑名单里。

**近似名**：前缀相同、编辑距离不超过 2 的名字可以起。品牌词的所有者可以在 30 天内提一次商标异议，对方二选一：改名，或付和解金（月收入的 10%，按 M.5.9 入账）。同一个名字只能被异议一次。

**查发布一律按 id**：按名字找发布的地方都写成 `relById(relId(名字))`，状态里照旧存名字（M.3.2）。真实发布表 312 行的 relId 没有重复，所以史实指纹不变。

**打榜**：
- 发布那天，世界给这一款的每个已上线基准打一次分，写进发布行。
- 分数 = `scoreFromX(benchX(dims) + 按 (relId, 基准) 散列出的噪声 + 发布时仍有效的刷榜增益)`。刷榜带来的污染照 model.js 的 `contamination` 记在行上。
- 换题以后，刷榜增益作废，按新一轮题目重算一次，所有人看到同一个新分。被曝光刷榜的，在榜单上打删除线。
- SOTA 只看 `qOf`，刷榜对标签没用。

#### M.5.5 股市

**上市**
- 条件：`ipoCheck` 原有的那些条件，再加两条：
  - V 不低于 30 亿美元，并且有两个季度的客户收入；
  - 原来的“2024 年起”换成 `P().ipoOpen`。
- 流程 90 天。挂牌时公司选发行比例：10%、20% 或 30%。
- 发行价 = V ÷ 总股本 × 0.85，公司拿到全部发行款。
- 发行的股票，一半放进做市池，由 NPC 做市资金配上等值的现金；另一半给 NPC 长线基金，这部分可以借给做空的人。
- 公司自己剩下的股份锁定 180 天。

**定价**
- 每家上市公司一个恒定乘积池（股数 × 现金 = k），手续费 0.3% 留在池里，不做订单簿。
- 每家公司每天对同一只股票的累计成交额，不超过池中现金的 5%（按天累计，拆单绕不过去）；每天涨跌不超过 ±20%。
- NPC 价值资金每天把价格往“V ÷ 总股本”拉，拉回对数差的 10%。V 从不读市价。
- 开仓、平仓、强平都用同一个池价。

**自家股票**：只能增发或回购，不能买卖，也不能做空。
- 回购价 = max(池价, V 每股价)；增发价 = min(池价, V 每股价)。两者都受每天 5% 的上限。
- 终局前 60 天禁止回购。
- 这样，股价被抬高时没法高价增发套现，被砸低时也没法低价回购占便宜。

**持股**
- 外部单一股东最多持有 25%。
- 持股达到 5% 要公示，之后每变动 1% 再公示一次。
- 持股达到 10% 的股东，能看到这家季报的具体数字；其他人只看到档位。

**做空**
- 可借的股票 = NPC 长线基金持股的一半，加上愿意出借的多头。
- 借券费年化 = min(150%, 1% + 60% × 占用率²)，按天扣。
- 开仓要押 150% 的保证金；跌破 130% 时，次日开盘强平：只从池里买回到保证金恢复 150% 为止，不一次全平。
- 一只股票的空头总量不超过池中股数的 15%。
- 当天跌了 10% 以上的股票，当天和次日都不能新开空单。

**股价管什么**：股价只影响炒股的盈亏和融资的难易，不进终局的公司价值（M.5.10）。所以抬别人的股价、砸别人的股价，都改变不了那家老板的身家。

**不做收购吞并**。一局 40–50 分钟，中途被吞的人就没得玩了，所以只留 25% 持股上限、公示和看季报这几样。

**复核**（`final/pump_fix.mjs`，规则全照上面）：

| 情形 | 结果（以被抬公司的公允市值为 100） |
|---|---|
| 一个账户最后 45 天每天买满，发行 10% | 30 日均价被抬到公允价的 2.28 倍；买方花了 16.0，持仓按整仓卖回只值 5.4，亏 10.5。旧口径下被抬那家老板的身家多出 e × 128；新口径下为 0 |
| 两个账户一起抬，发行 30% | 均价被抬到 5.23 倍；买方亏 110.7；被抬那家身家仍然不变 |
| 小号买、主号卖（对倒送钱） | 主号多赚 1.7–5.1，小号亏 8.3–25.0，送钱效率 0.2 |
| 现金买股票再换回 | 身家只少手续费加滑点，约 0.55% |

#### M.5.6 挖人（可选，大厅里默认关）
- 命令 `poach(target, n)`：挖对方团队的 3%，每人付 2 倍年薪。成功率看双方口碑、股价走势和对方的士气；对方可以加薪留人。
- 挖成以后：
  - 对方 60 天内研究速度 ×0.8（现有的 `due.poach`）；
  - 挖人的一方得到的技术积累，是对方损失的一半；
  - **不转移任何技术**，防止盟友互挖来交换独门技术。
- 同一对公司 180 天内只能挖一次。

#### M.5.7 新手保护
- 开局后 120 天内，谁都不能被做空、被挖人。上市满 180 天之前，也不能被做空。
- 保护只给受害的一方：违规照样检测、照样记账，保护期一过，就可以追究。

#### M.5.8 破产、重组与清算
- 现金连续 60 天为负，由债权人重组。**每家一局最多重组 1 次。**
- **重组的钱不凭空造**：
  - 按买价的 5 折卖卡；
  - 不够的部分，按 V 每股价的一半向 NPC 债权人增发；
  - 补到够 3 个月开销为止，而且补完的现金不超过清算价值。
  - 老股东最多剩 30%；团队 ×0.7。
- 重组后 180 天内，M.5.9 列的转钱渠道这家全部用不了，进出都不行，也不能买卖别家股票。
- 第 2 次现金连续 60 天为负，直接**清算**：
  - 公司冻结：不能交易、不能买 API、不能租卡；
  - 持仓和空头按清算价平掉；
  - 身家 = e × max(0, 清算价值)；
  - 这个人转为旁观，还能聊天。

#### M.5.9 钱从哪条路流到别家（按有人开小号来设计）

**总规则**
- 公司之间的一切转账，付的一方付 100%，收的一方只入账 60%（`TRANSFER.BOOK`），其余 40% 记作推理成本、税和律师费。
- 这些钱一律不算客户收入，不进估值池的收入项，也不进 IPO 门槛。
- 玩家之间没有直接转账。

| 渠道 | 损耗和上限 |
|---|---|
| 买卖股票 | 手续费、滑点、单日上限、价值资金拉回；实测送钱效率 0.2 |
| 闭源 API 蒸馏 | 入账六成；同一对公司每个游戏年最多 2 个数据包；有被查出的风险 |
| 受限开源分成 | 5%，只在衍生模型份额 ≥ 15% 时才有，按衍生方的客户收入算；入账六成；公开可查 |
| 租卡 | 只经过共用租卡池，现货价；公司之间不能直接租 |
| 商标和解金 | 每个名字只能被异议一次；入账六成 |
| 官司赔款 | 最多是已付费用的 3 倍；入账六成 |

**M2 验收的“小号送钱”脚本**：一个同档小号用上面全部渠道（再加上故意破产）给主号送 2 年钱。主号身家比没有小号时最多高 10%，而且送钱效率不超过 30%。

#### M.5.10 终局身家与称号
- **身家** = 自家持股比例 `s.equity` × 公司价值。
  - 公司价值：上市的取 V，未上市的取 V × 0.8（流动性折价）。
  - V 里已经按清算价算了持仓和空头（M.3.8 第 4 条），所以现金换成股票、再换回来，身家只少手续费和滑点；也不会把炒股持仓按 100% 再加一遍。
- **称号**：持标天数最多、炼出 SOTA 次数最多、份额峰值最高、被派生最多的开源模型、抓到蒸馏最多、市值最高（按 30 日均价，只是称号，不进身家）。

### M.6 联机

#### M.6.1 网络结构：权威服务器按天结算，不用锁步

**不用锁步，原因有四条：**
1. 引擎里有 29 行 `exp`、`log`、`pow`，不同浏览器算出来的最后一位可能不同；
2. 锁步要求每台机器都有全量状态，别人的现金和在练模型只能靠界面藏，打开控制台就能看到；
3. 一天要 0.5–3 秒才走一步，网络延迟感觉不到；
4. 状态小，快照、重放、重连都便宜。

**传输**：SSE 下行，HTTP POST 上行，只用 `node:http`，零依赖。

**下行流量实测**（`final/diff2.mjs`，和上一轮检查用的 `check/diff_real.mjs` 同一口径：现有机器人、qwen y2023、deepseek y2024、gpt y2025）：

| day 事件的写法 | 每家每天中位 / p90 | 2 档（2 秒一天）每客户端 |
|---|---|---|
| 顶层键差分（上一版） | 15.2–17.3KB / 28–49KB | 约 7.5KB/s，超过验收线 |
| **二级差分（定稿）**：`s.models` 按模型 id 再按字段比，只发变了的模型和字段；`news`、`log`、`history` 只发新增条目；其余顶层键变了才整个发 | 1.3–1.5KB / 3.8–5.1KB | 1.0–1.1KB/s |
| 二级差分 + 整条 SSE 流用一个 deflate 流压缩、每天 flush 一次（可选） | 0.17–0.20KB / 0.6–0.7KB | 0.17KB/s（4 档 0.69KB/s） |

世界公开部分的差分（新发布行、标签、新闻、价格）另算，一天通常只有几百字节。

#### M.6.2 进程
- 主线程管 HTTP、SSE 和大厅。
- 每局一个 `worker_threads`：引擎里全是模块单例，一个线程只能放一个世界。
- 实测（`server-first/worker_iso.mjs`）：1 号局清空了发布表，别的局仍是原样；每局启动 0.3 秒，约 40MB。

#### M.6.3 推进、调速、暂停
- **速度**：4 档，一天分别是 3 秒、2 秒（默认）、1 秒、0.5 秒。实际速度取在线真人投票的中位数，人数为偶数时取慢的那档；电脑和掉线的人不投票。
- **暂停**：
  - 谁都能按暂停。每人每个游戏年 3 次，每次最多 60 秒；暂停满 30 秒后，任何人都能点继续。房主不限次数。
  - 所有真人都投了暂停，就不限时。
  - 所有真人都掉线时，自动暂停并存档。
- **掉线保护**：
  - 有人掉线时，全局先暂停，最多 2 分钟，每局最多 2 次（按局计）。
  - 到点没回来，或者这两次已经用完（这时等 60 秒），他的公司就交给被动档托管，时间接着走。
  - 人回来立刻交还。

#### M.6.4 收件箱
- 联机里卡片不挡时间，进收件箱。期限取下面两个里较长的：10 个游戏日，或 45 秒现实时间。
- 到期没处理，按顾问推荐的选项处理；没有推荐的，选第一个不在 `AVOID` 里的选项。蒸馏指控卡默认“封号不声张”。
- **重大卡降速**：有人手上压着重大卡（超事件、专属事件、带选项的里程碑、蒸馏指控卡）时，全局临时降到 1 档，处理完恢复。
  - 每人每个游戏年累计造成的全局降速不超过 3 分钟，超过以后他的重大卡不再拖慢别人。
  - 托管中的公司，卡片当场按默认项处理，不触发降速。
- **按下标处理**：M0 把 `resolveEvent(s, choiceId)` 扩成 `resolveEvent(s, choiceId, at = 0)`，`currentEvent(s)` 扩成 `currentEvent(s, at = 0)`。下标默认 0 时行为不变；收件箱按下标处理任意一张到期的卡。

#### M.6.5 命令协议
- **发命令**：`POST /api/r/:room/cmd {v:1, seq, name, args}`。座位令牌放在 HttpOnly、SameSite=Strict 的 cookie 里，不进 URL。
  - 返回 `{ok, seq, day}` 或 `{ok:false, seq, err}`；同一个 seq 重发，返回同样的结果。
- **唯一入口和唯一参数表**：`sim/commands.js` 里的 `COMMANDS = { name: { fn, args } }` 和 `applyCommand(s, { name, args }, ctx)`。
  - 界面的 `guard` 和服务器共用这一个入口：先按参数表校验，再交给引擎；引擎抛错就把原话回给客户端。
  - `net/protocol.js` 从这里导入参数表，不另写一份。
- **命令清单**（只收 P4.1 之后还在的出口，协议只加不改）：

  | 组 | 命令 |
  |---|---|
  | 训练作业（T11.2） | `startJob`（底座、蒸馏、续训、后训练、试验都走它）、`cancelJob`、`pauseJob`、`setJobPrio`、`setJobCap`、`setPost`、`setRush`、`setRepair`、`setAutoRepair`、`setOwnOnly`、`setPlan`、`focusResearch`、`submitEval`（参数里另带 `papers`、`licenseTerms`；tier 为 `skip` 时当天发布）、`cancelEval` |
  | 其余引擎命令 | `decide` 只收 `data`（买数据、下生成订单）和 `eval`（跑分）两个动作；`researchTech`、`stopTech`、`buyGpu`、`buySmuggled`、`releaseGpu`、`setInferShare`、`setLease`、`setProduct`、`setTier`、`setSmallApi`、`setRouting`、`setPolicy`、`trade`、`startFunding`、`startIpo`、`startStrategy`、`cancelStrategy`、`resolveEvent`（带下标）、`applyAdvice` |
  | 互动命令（M2 追加进 `sim/commands.js`） | `short`、`cover`、`lend`、`buyback`、`ipoIssue`、`distillReply`、`setLicenseTerms`、`trademark`、`poach` |
  | 房间命令（不进引擎） | `vote`、`pause`、`resume`、`ready`、`chat`；房主专用：`kick`、`approveSeat`、`settings`、`save` |
  | 系统命令（服务器自己发，写进日志） | `sys.autoResolve`（收件箱到期）、`sys.host`、`sys.unhost`（托管和交还）、`sys.takeover`（中途接管电脑公司）、`sys.dropPause` |

  - 兼容出口一律不进协议：`setFocus`、`setPush`、`startProject`、`startDistill`、`startFinetune`、`cancelProject`，以及 `decide` 的 `maintain`、`research`、`train`、`idle`、`pretrain`、`release`。所以 P4.1 删掉它们时，`commands.js` 不受影响。
- **SSE**：`GET /api/r/:room/events`，每条事件带 `id`（世界序号）。
  - `init`：自家完整的 `s`（去掉 `rng`、`seed`）、世界的公开部分、座位表；
  - `day`：日期、自家 `s` 的二级差分（M.6.1）、世界公开部分的差分；
  - 另有 `inbox`、`clock`、`lobby`、`chat`、`end`，以及每 20 秒一次的 `ping`。
- **客户端不跑 `tickDay`**：MirrorProvider 把公开的发布行和标签镜像灌进同一套引擎单例，页面代码基本不用改。`jobCheck`、`previewProject` 这类预估在本地算，界面上标“预计”，以服务器为准。

#### M.6.6 谁能看到什么

| 人人看得到 | 只给档位 | 只有自己知道 |
|---|---|---|
| 已发布的模型：名字、分数、榜单成绩、开闭源、许可、公开的“派生自”（续训底座和开源老师）、价格档；SOTA 标签和换手；行业第一次；公开到 proof 以上的技术；股价、成交量、5% 以上的持股、空头总量；上市公司季报的档位；融资和 IPO 公告；官司结果；公共新闻；月度份额；“某个名字已被预订”（不说是谁） | 卡数（如“千卡级”）、团队规模、未上市公司的收入和现金 | 现金明细；作业表、分卡、在练模型和进度、送评中的候选（`s.jobs`、`s.evals`）；研究；没公开的首创技术；策略；数据和订单（含蒸馏单和抽取量）；**完整血统 `kin`（含 API 老师和合成教材带来的污染）**；事件抉择；`s.rng`、`s.seed` |

- 持股达到 10% 的股东，能看到那家季报的具体数字。
- 一局结束后公开全部隐藏信息，生成复盘页（M.7）。
- 训练页的难度那一行，在联机里不显示锚点的数值，也不显示锚点是哪一款；“差几分”按世界可见的最强算（D6.6）。这样没法反推出谁的发布因为血统被排除了。

#### M.6.7 断线、存档、回放
- **断线重连**：服务器保留最近 300 条事件，差得少就按 Last-Event-ID 补发，差得多就重发 `init`。
- **存档**：每局一个目录。
  - `meta.json`：设置、座位、引擎提交号；
  - `snap-<天>.json.gz`：每 30 个游戏天一份全量快照，带 `world.rels`；保留最近 3 份和每年 1 份；
  - `log.ndjson`：玩家命令、投票、聊天，以及全部系统命令，每行带 day 和 seq；
  - 每 30 天记一次状态哈希。
- **一切看墙上时钟决定的事，都先变成系统命令再执行**：收件箱 45 秒到期、掉线 60 秒转托管、交还、中途接管、掉线暂停。所以重放时世界不会走岔。
- **崩溃恢复**：读最近一份快照，再重放日志尾巴。在同一个 Node 上重放，结果逐位一致。
- **保留期**：房间在服务器上保留 14 天，一局可以分几个晚上打完，续玩时处于暂停状态。
- **引擎升级**：只保证能从快照接着玩，不保证旧日志能重放。

#### M.6.8 防作弊与一人一座
- 状态只在服务器上，每个座位只能给自己的公司下命令。参数表和引擎做双重校验。随机数全在服务器上。聊天和名字一律当纯文本显示。
- 限流：每个座位每秒最多 10 条命令，聊天每秒 1 条；请求体不超过 8KB。
- **座位**：
  - 每个座位都要房主批准，开局前也一样；
  - 一个浏览器（cookie）只能占一个座位；
  - 同一个 IP 占了多个座位时，提示房主，但不自动拦，因为一家人可能共用一个网；
  - 中途加入只能接管电脑公司。
- 同一个座位最多开 3 条 SSE（电脑加手机同时看），从任意一条发的命令都算。

#### M.6.10 部署
- **服务**：`server/mp.mjs`，零依赖，只用 `node:http`、`node:worker_threads`、`node:zlib`、`node:crypto`，需要 Node 22 以上。静态文件和接口由同一个进程提供。
  - 启动参数：`--port`（默认 8790）、`--host`（默认 127.0.0.1）、`--max-rooms`（默认 4）。
- **本地先测**：
  - 运行 `node server/mp.mjs --port 8790 --host ::`，双栈监听，[::1] 也能连上；不碰 8765。
  - 用 127.0.0.1、localhost、[::1] 开三个窗口当三个人，cookie 天然分开。
  - 再开一个手机尺寸的窗口，它和前三个窗口之一共用 cookie，算那个人的第二个视图。
  - 另外用 `scripts/mp_soak.mjs` 起无头客户端；压测时可以临时 `--max-rooms 8`。
- **线上放 hz**（主机名 Atonelia，内存 3.7G）：
  - hz 从 2026-10-15 起还跑着正式站：galbands.com 和 benchmark.galbands.com（服务 `galbands-site`，端口 8788，SQLite），以及 MaiBot 的两个容器。所以游戏服务要做资源隔离。
  - 代码放 `/opt/model-raising/`，systemd 单元叫 `atonelia-mp`，只监听 127.0.0.1:8790。
  - 单元里写：`MemoryMax=1G`、`CPUQuota=`（先 `ssh -t hz nproc` 查核数，取核数 × 50%）、`Nice=10`；启动参数加 `--max-old-space-size=512`。同时最多几局，按 hz 上的实测定，默认 4。
  - 先用 `ssh -L 8790:127.0.0.1:8790 hz` 自测。
- **制作人说“上线”以后，才加公网主机名 `atonelia.galbands.com`**（被占用就改成 `mp.galbands.com`，并在部署说明里写明）。
  - 部署说明（`deploy/README.md`）第一步：先查清 hz 上的 Cloudflare 隧道是怎么管的：
    - `ssh -t hz sudo cloudflared tunnel list`
    - `ssh -t hz sudo cat /etc/cloudflared/config.yml`
    - `ssh -t hz systemctl cat cloudflared`
  - **本地配置文件管理的**：在 `config.yml` 的 ingress 里加一条 `hostname: atonelia.galbands.com → service: http://127.0.0.1:8790`，放在兜底规则之前。然后 `sudo cloudflared tunnel route dns <隧道名> atonelia.galbands.com`（用 hz 上这条隧道自己的证书；现有的 Cloudflare API 令牌没有 DNS 权限，不能用它），再 `sudo systemctl restart cloudflared`。
  - **面板管理的**（服务用 token 启动）：由制作人在 Cloudflare Zero Trust 面板 → Networks → Tunnels → 这条隧道 → Public Hostname → Add，填子域名 `atonelia`、域 `galbands.com`、服务 `HTTP`、`127.0.0.1:8790`。
  - 说明里每一步都写成能直接复制的命令或面板路径。
- **不放 vps**：vps 只有 1 核 2G，还跑着代理节点和 CPA 网关，不能动。
- **心跳**：SSE 每 20 秒发一次。Cloudflare 隧道空闲约 100 秒会断（二手资料），M5 实测确认。

### M.8 平衡

**防滚雪球**：全部来自同一套规则，不给落后的人开小灶。
1. 锚点不含自己，也不含血统里有自己的发布（含学界行）：领先越多越难再涨，盟友陪跑抬不动。
2. 靠堆算力让底座跳一大步以后，后训练几乎停住，要等别人追上来。
3. 领先者一开源或发论文，学界水平就跟着涨，落后者离锚点更远，涨得更快；领先者自己的 `fLead` 少一项。
4. 蒸馏追得快，但超不过老师。
5. 市场 logit 有饱和，还有“不用 AI”这个选项。
6. 共用算力池季末统一定价，大买家把价格抬高，所有人（包括自己）付同一个价。
7. 估值池总量有上限；冠军拿不到标签要挨罚（D11）。
8. 估值高的公司会成为做空目标，但做空只影响炒股盈亏，不动对方老板的身家。

**新手保护**：见 M.5.7。**电脑难度**：见 M.3.12。

| 时长 | 纯推进 | 算上暂停和处理卡片 |
|---|---|---|
| 1 年 | 12 分钟 | 20–25 分钟 |
| 2 年（默认） | 24 分钟 | 35–50 分钟 |
| 3 年 | 37 分钟 | 55–75 分钟 |

**校准**：
- 只调 §1.3a 里的数：`data/selfplay.js`、`data/exchange.js`。
- 不动 D6 常数、缩放律、`balance.js`，所以史实模式不受影响。

### M.10 风险与已定的做法
1. **前沿停滞和进步速度。**
   - 原型 58 局主配置里，世界最强连续不涨的最长天数中位 202 天、p90 239 天（真实历史最长 237 天，是 2023 年 GPT-4 到 GPT-4 Turbo）。
   - 进步速度大约是真实历史的六成（从第一款发布算起，中位 0.62 倍）。
   - **大厂档 2025 年开局不达标**：种子 11 停了 360 天、每年只涨 2.7 分；种子 13 每年 2.9 分。原因是开局技术少了 MoE 和推理，第二个底座没比第一个强。
   - M1 能调的只有这几样：
     - `SUPPLY_SELF.MULT`；
     - `SELF.BOT_HORIZON`；
     - `SELF.EFFORT_REF` 和 `SELF.EFFORT_FLOOR`；
     - `ACAD.TECH_GAIN`；
     - 电脑发论文的规则。
2. **放开缩放律以后，会不会有人靠一次超大预训练甩开所有人？** 有四道闸：共用算力池的季末统一价、T 章的工期上限（365 天）、越线以后后训练停住、开源抬地板。验收看 F4a 的“领先第二名超过 8 分、持续 180 天以上的局数为 0”（原型最长 63 天）。
3. **学界会不会又变成一条预设线？** 学界只由公司行为推动，永远在公司最强之下，起点也按本局设置算。全员闭源的局里它一动不动。
4. **发布表是模块单例。** 一个进程只放一个世界：服务器每局一个 worker；浏览器里离开自洽模式（回标题页、开史实局）一律整页重载。
5. **有些卡片假定“必须马上选”。** 全部进收件箱，有期限；重大卡让全局降速，而且有上限，不会让时间停下。
6. **非 LLM 模态。** v1.1 不开。开放之前要先重做出生护栏这一条，因为 `nonLlmBase` 出生时就接近满额。
7. **手机性能。**
   - 原型 12 家 730 天在 Node 里 1.4 秒（约 0.16–0.2 毫秒/家/天）。
   - M1 在手机尺寸上实测：12 家每天超过 150 毫秒时，开局设置页自动把上限降到 8 家；分岔局按 `SELF.FORK_KEEP` 减家。
8. **和 §0.3 的关系。** “对手不跑策略树”只约束史实模式。“IPO 锁进策略”指的是 IPO 不靠策略节点解锁，和股市的锁定期是两回事。
9. **蒸馏检测概率定得准不准。** M2 用困难电脑校准，目标是每局被查出 0.5–1.5 次，只调 `DISTILL_WATCH.BASE`。
10. **小号。** 经济规则已经按有人开小号来设计（M.1 第 6 条）。大厅还有“每座房主批准”和“同 IP 提示”两道闸。
11. **hz 和正式站共用一台机器。** 有资源配额；M5 在 hz 上实测正式站延迟。出了问题先停 `atonelia-mp`，正式站不受影响。
